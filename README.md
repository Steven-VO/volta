# Volta

Volta generates **k-polycirculant graphs**: graphs with an automorphism that
splits the vertices into a few cycles (orbits). You give the orbit lengths,
and Volta lists every such graph, optionally only those with given properties:
no `K_r`, no independent set of size `s`, girth at least `g`, chromatic number
at most `c`, prescribed degrees, and more. The filters cut the search early;
they are not applied afterwards.

Prescribing such a symmetry shrinks a graph on `n = km` vertices to about
`k²m/2` bits, so the search can be exhaustive far beyond the range of
unrestricted graph generation. Extremal graphs are often symmetric, so this
makes a good heuristic search for graphs with a given property. Ramsey graphs
are one example: `volta 17 -f K4 -F K4` finds the Paley graph on 17 vertices.

```
$ volta 8,8,8 -r 3 -g 7 -6          # cubic graphs of girth >= 7 with an automorphism 8+8+8
WhCGKE?O@?A?AG@C?P?AG?G??O??O??GO?AC??Q_?@I??AS
W?`@?a?O@?A?A?@??O?A?_?T?_`?__`O?GS?@A_?CI??GS?
volta 1.0   orbits = 8,8,8   n = 24
conditions: girth >= 7, 3-regular
graphs (N-classes) = 2
time = 0.000 s
```

(Both lines are the McGee graph, the (3,7)-cage; see
[What is generated](#what-is-generated) for why it appears twice.)


## Requirements

* a POSIX shell and the usual command-line tools (Linux, macOS, BSD, WSL);
* a C++20 compiler: `g++` 10 or later, or `clang++` 12 or later.

nauty (`shortg`, `geng`, ...) is optional and pairs well with Volta's graph6 output.


## Installation

Nothing has to be built in advance. Unpack or clone the repository and run the
`volta` script:

```
$ ./volta 5,5
```

The first run of a parameter set compiles a binary for it, which takes about
two seconds and prints a note. The binary is cached, so later runs start
immediately (see [Compilation and the cache](#compilation-and-the-cache)).

To install the script and the sources:

```
$ make install                    # into /usr/local (bin/volta, share/volta)
$ make install PREFIX=$HOME/.local
```

To run the test suite (about a minute; it compiles some 100 parameter sets in
parallel and compares the results with known counts):

```
$ make check
```


## What is generated

`volta m_0,m_1,...,m_{k-1}` considers the vertex set made of `k` orbits
`O_i = {(i,0), ..., (i,m_i - 1)}` and the permutation `phi` that rotates each
orbit: `phi(i,j) = (i, j+1 mod m_i)`. The lengths may differ, but each must
divide the largest one, `m`. A graph is **k-polycirculant** with these orbits
when `phi` is one of its automorphisms. With `k = 1` these are the circulant
graphs, with two equal orbits the bicirculants, and so on. Every graph with an
automorphism whose cycles have the lengths `m_0, ..., m_{k-1}` is isomorphic to
one of them.

Such a graph is determined by `k(k+1)/2` connection sets. Equivalently, its
edge set is a union of orbits of `phi` on the vertex pairs: its **edge
orbits**. Throughout Volta, an edge orbit is an orbit of `phi` (that is, of
the cyclic group generated by `phi`), not of the full automorphism group of
the graph, which can be larger.

Volta lists the graphs by **orderly generation**: it produces exactly one
graph from every class of the equivalence "one is mapped onto the other by a
relabelling that keeps `phi` an automorphism". Such a relabelling is an
element of the normaliser `N` of `phi`: it multiplies all positions by a unit
of `Z_m`, shifts each orbit, and permutes orbits of equal length. These classes are the **N-classes** that Volta counts.

N-classes are not isomorphism classes. Two graphs can be isomorphic through a
map that does not normalise `phi`, for instance when a graph has several
inequivalent automorphisms of the given shape. For example, `6,6,3` gives
16 720 N-classes, which are 16 336 isomorphism classes. Where it matters,
remove the duplicates afterwards with nauty:

```
$ volta 6,6,3 -6 2>/dev/null | shortg -q > unique.g6
```

In the graph6 output vertex `(i,j)` has the number `m_0 + ... + m_{i-1} + j`
(orbits are consecutive blocks, in decreasing order of length). The rotation
`phi` is therefore the same permutation for every graph in the file.

**Limits:** at most 6 orbits, the largest orbit length at most 64, and every
length must divide the largest. This allows up to 384 vertices, but what is
feasible depends on the number of graphs, i.e. on how strong the filters are.


## Usage

```
volta ORBITS [options]
```

`ORBITS` is a comma-separated list of orbit lengths, e.g. `17`, `8,8,8`,
`12,12,4`.

### Properties of the graphs

All of these can be combined.

| option | meaning |
|---|---|
| `-f`, `--forbid LIST` | no subgraph from `LIST` (see below) |
| `-F`, `--co-forbid LIST` | the same for the complement |
| `-g`, `--girth G` | girth at least `G` (no cycle shorter than `G`) |
| `-c`, `--chi C` | chromatic number at most `C` |
| `-d`, `--mindeg D` | minimum degree at least `D` |
| `-D`, `--maxdeg D` | maximum degree at most `D` |
| `-r`, `--regular D` | `D`-regular |
| `-w`, `--forward` | forward checking (see below) |

`LIST` is a comma-separated list of at most one of each kind of:

* `Kr`: the complete graph on `r` vertices. `-f K4` means no 4-clique, and
  `-F K5` means no independent set of 5 vertices. `-f K2` leaves only the
  graph without edges.
* `Kr-e`: the complete graph on `r` vertices minus one edge. `-f K4-e`
  (no diamond) means that no edge lies in two triangles. `K3-e` is the path
  on 3 vertices, so `-f K3-e` leaves the matchings.
* `Cl`: the cycle of length exactly `l`. `-f C4` forbids 4-cycles only, while
  `-g 5` forbids every cycle shorter than 5.

`-f Kr -F Ks` gives the `(r,s)`-Ramsey graphs among the polycirculants.

**Forward checking** (`-w`) does not change the output. Before branching, it
tests every undecided edge orbit (orbit of `phi` on the vertex pairs) against
the `-f`/`-F`/`-g` filters and fixes those that are forced: an orbit that would
create a forbidden subgraph must consist of non-edges, and an orbit whose
absence would create a forbidden subgraph in the complement must consist of
edges. This propagation costs time at every node, so
whether it pays depends on the case. It typically pays off with `-F` near a
Ramsey bound (often 4 to 17 times faster) and with `-g` (about 3 times
faster). Where almost every node is a reported graph, it can cost a few tens of
percent. When in doubt, time both on a smaller case.

### Output

| option | meaning |
|---|---|
| `-6`, `--graph6` | write the graphs to standard output in graph6 format; the summary goes to standard error |
| `-o`, `--output FILE` | write the graphs to `FILE` in graph6 format |
| `-v`, `--verbose` | a longer summary (see below) |

Without `-6` or `-o` only the summary is printed. It gives the orbits, the
conditions, the number of graphs and the running time:

```
$ volta 6,6,3 -f C4
volta 1.0   orbits = 6,6,3   n = 15
conditions: no C4
graphs (N-classes) = 139
time = 0.000 s
```

With `-v` it also gives the parameters of the search (the word length, the
threads and tasks, and for graph6 output the numbering of the vertices), its
statistics (nodes of the search tree, filter checks, forced orbits), and the
number of graphs by number of edge orbits and by number of edges.

With several threads the order of the graphs in the output depends on the
schedule. The set of graphs does not.

### Long runs: threads and parts

| option | meaning |
|---|---|
| `-t`, `--threads N` | worker threads (default 1; `0` = one per CPU) |
| `-s`, `--split D` | depth at which the search tree is cut into tasks for the threads (default 7) |
| `-p`, `--part R/M` | run only part `R` of `M` (`0 <= R < M`) |

The search tree is cut at depth `D` into tasks, which the threads share. The
depth of a node is its number of edge orbits (orbits of `phi` on its edges).
A few hundred to a few thousand tasks balance well. With many threads a deeper
split (8 or 9) can help.

`--part` spreads a run over several processes or machines. Each part runs
every `M`-th task, and the `M` parts together produce every graph exactly once:

```
$ volta 30,30 -f K4 -F K9 -w -p 0/64 -B          # compile once, before starting the parts
$ seq 0 63 | xargs -P 8 -I{} sh -c 'volta 30,30 -f K4 -F K9 -w -p {}/64 -o part{}.g6 2> part{}.log'
$ cat part*.g6 > all.g6
```

On one machine `-t` is simpler. Parts are meant for several machines or batch
jobs, e.g. machine `j` of 4 runs the parts `j, j+4, j+8, ...` of 64. Every
part repeats the (short) phase that collects the tasks, so use parts for long
runs. Compile once (`-B`) before starting the parts, so they do not all
compile at the same time.

### Compilation and the cache

| option | meaning |
|---|---|
| `-B`, `--build-only` | compile only, and print the path of the binary |
| `-n`, `--dry-run` | print the compile and run commands, do nothing |
| `--rebuild` | compile even if a cached binary exists |
| `--clear-cache` | remove the cached binaries |
| `-h`, `--help` | help |
| `-V`, `--version` | version |

Everything that defines the parameter set (orbits, filters, graph6 output,
parts) is fixed at compile time. That is what makes the generator fast: the
compiler specialises all loops and tables, and code for unused filters does
not exist. Threads, split depth and the part number are run-time options and
do not cause a recompilation.

The binaries are kept in `$VOLTA_CACHE`, by default
`${XDG_CACHE_HOME:-~/.cache}/volta`, in a subdirectory per compiler, CPU (they
are compiled with `-march=native`) and version of the sources. A home
directory shared by different machines is therefore safe. The binary of a
parameter set can also be run directly; it accepts `-t`, `-s` and `-p`.

Environment variables:

* `CXX`: the compiler (default: the first of `g++`, `c++`, `clang++`);
* `CXXFLAGS`: replaces the default optimisation flags `-O3 -march=native`;
* `VOLTA_CACHE`: the cache directory.


## Examples

```
volta 5,5                         # all 48 N-classes of bicirculants on 10 vertices
volta 1,1,1,1,1,1                 # 156: all graphs on 6 vertices
volta 17 -f K4 -F K4              # the (4,4)-Ramsey graph on 17 vertices (Paley)
volta 13 -f K3 -F K5 -6           # the (3,5)-Ramsey circulant on 13 vertices
volta 7,7 -r 3 -g 6 -w -6         # the Heawood graph
volta 8,8 -f K4-e -r 3            # cubic diamond-free bicirculants on 16 vertices
volta 12,12,4 -c 2 -t 0           # bipartite graphs, all CPUs
volta 6,6,6 -d 4 -D 6 -o out.g6   # degrees between 4 and 6, into out.g6
volta 9,3 -c 3 -f K4 -w           # 3-colourable K4-free graphs
```
